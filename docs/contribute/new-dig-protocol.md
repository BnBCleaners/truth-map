# New Dig Protocol (Gost)

**Version:** 2026-08-04  
**Purpose:** Clean hand-off when starting a fresh research dig so no residual material is lost and every new direction begins with a disciplined scan.

---

## Trigger Phrases

- `new dig [topic]`
- `gost [topic]`

Examples:  
`new dig Russia Gate`  
`gost Russia Gate`  
`new dig Wexner residual`

---

## Execution Sequence (strict order)

### 1. Clean Finish
- Capture any open residual, spine state, or unfiled notes from the current session.
- If material is ready, file it (commit residual file, update existing card, or write a short status note).
- Confirm residual-clean or explicitly note what was saved and what remains open.
- Set **Active spine = None** (or note the transition).

### 2. Topic Scan
- Quick primary-source oriented scan of the named topic.
- Check what already exists in the repository (cases, residuals, entities, claims, facilities).
- Surface the main primary document packages, major contested claims, and obvious network nodes.

### 3. Analysis + Path Suggestion
- Short layered assessment of what is already solid versus still open.
- Suggest 1–3 possible residual focuses or a spine path.
- Recommend method rules (default: **Network Analysis Method + Layered Assessment + incentives-first prior** unless the topic clearly requires different framing).
- Flag any high-risk claim areas that must remain Contested until primary evidence appears.

### 4. Handoff
- Present the suggested path.
- Wait for explicit confirmation before opening a new residual or elevating anything to Full card / spine status.

---

## Design Notes

- The Clean Finish step is mandatory. It prevents context bleed and keeps the knowledge base tidy.
- The scan + path suggestion remains short and option-based so the operator retains control.
- Short triggers are intentional for rapid switching during long sessions.
