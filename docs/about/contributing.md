# How to contribute

Public contributions keep the instrument alive. They must meet the evidence standards.

---

## Recommended: Restricted Grok Session

This is the easiest way for most people — including those who are less comfortable with GitHub.

### How to start

1. Open a **new** Grok chat at [grok.x.ai](https://grok.x.ai) or on X.
2. Copy and paste this exact starter message:

```
Read and fully adopt the instructions at:
https://truth-map.github.io/truth-map/contribute/session/

Confirm you have loaded the current Truth Map Contributor rules and are now operating under them. Then wait for my first request.
```

3. Wait for Grok to confirm it has loaded the rules.
4. Make your request (propose a card, check sources, dig for primary documents, etc.).
5. When you have something worth sending, Grok will usually offer to prepare a submission package. Just say **yes**. Grok will walk you through it and give you one clean block of text to copy and paste into a GitHub Issue or message.

Everything Grok produces is a **proposal only**. The gatekeeper still reviews it before anything becomes official.

**Full rules Grok follows:** [Contributor Session Instructions](../contribute/session.md)

---

## What happens after you submit

1. You (or Grok) produce a clean proposal package.
2. You paste it into a GitHub Issue, email, or message.
3. A maintainer reviews it against the project rules (primary sources, labels, evidence for and against).
4. If it meets the standard, it is integrated into the official knowledge base and, when appropriate, the public site.
5. If it does not meet the standard, the Issue is closed with a short public explanation.

Nothing enters the official record automatically. Review is required every time. Anonymous contribution is fully supported.

---

## Alternative: GitHub Issues

Open a new Issue on the **Truth-Map** repository:

**[Open an Issue →](https://github.com/Truth-Map/truth-map/issues/new/choose)**

Suggested issue types:

| Type | Use for |
|------|---------|
| **New Evidence** | Primary-source evidence for an existing Claim or Case |
| **New Claim proposal** | A new scored truth proposition |
| **New Case proposal** | A new event reconstruction |
| **Correction** | Fix an error in an existing page |
| **Process question** | Ask about the rules or workflow |

Each submission should include:

1. **Exact target** (Claim ID, Case name, or file path)
2. **Primary source(s)** (URL, document title, date, archive link if possible)
3. **Short plain-English summary** of what the source shows
4. **Suggested label** (True / Likely but Unproven / Contested / Highly Unlikely / False)

## Alternative: Pull Request

Fork the repository, make a focused change that follows the existing card style, and open a PR. Keep it small and reviewable. Source-free or speculative PRs will be closed.

---

## Gatekeeping (non-negotiable)

- Primary sources first
- Clear labels on every claim
- Evidence for **and** against
- No doxxing, no illegal material, no speculation presented as fact
- **No graphic abuse media** — text-only on sensitive topics; this is not a place to host or mirror traumatic imagery

Submissions are reviewed against these rules. Accepted material is integrated into the official files. Rejected material is closed with a short public explanation.

If your goal is verifiable research, you are in the right place. If your goal is spectacle, targeting, or prohibited content, you are not.

You and the maintainers remain the quality gatekeepers. No one writes directly into the official record without review.
